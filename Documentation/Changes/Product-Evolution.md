# Product Changes

## Repository Changes

1. The use cases were adjusted to match the updated requirements list, since the requirements were consolidated, rewritten, and re-prioritized.
2. The use case diagram was modified so that it reflects the adjusted use cases and stays consistent with the documented behavior.
3. The overall process was revised by adding new steps and modifying existing ones, because the changes in requirements and use cases left some steps outdated or incomplete.
4. A designs folder containing the prototype and its verification was added to keep the design artifacts organized and to show that the prototype was checked against the requirements.
5. Spelling and wording errors were corrected to improve the clarity, readability, and professionalism of the documentation.
6. The video and slides for the second deliverable were added to the presentation folder to keep all project evidence centralized and accessible.

## Requierement Changes 

1. A priority justification was added to every requirement, tying each priority level to user needs and system scope.
2. Overlapping or redundant requirements were consolidated into single, cohesive requirements.
3. Requirements were rewritten to be specific, unambiguous, and verifiable, replacing vague wording with concrete details.
4. Acceptance criteria were added to the non-functional requirements so that compliance can be objectively verified.
5. A requirement that combined multiple concerns was decomposed into two independent requirements, so that each one can be implemented, tested, and traced individually.
6. Requirement priorities were re-evaluated and adjusted based on their impact on the core user flow.
7. Requirements that were not feasible to implement or that did not constitute verifiable requirements were removed.
8. Functional and non-functional requirements were linked to one another to establish traceability, so that each quality constraint can be tied to the functionality it affects.
